# Ship AgencyDiff before the Nov 4 deadline

AgencyDiff can be built on documented, publicly readable Meta APIs. The biggest risks are the rules and the measurement design, not the APIs. Submissions are due **Wednesday, Nov 4, 2026 at 9:00 PM ET (02:00 UTC Nov 5)**, which leaves a solo builder about 7.5 days from Oct 28 ([Meta event page](https://dev.meta.ai/events/global-hackathon)). The official Indie criterion is **"creativity, technical ambition, and whether it works"**. The Official Rules document, which covers video length, repo visibility, pre-existing code and non-Meta models, could not be retrieved. Every detail about those comes from unofficial sources and must be checked in the Cerebral Valley dashboard. On the technical side, Muse Spark has a native `computer` tool on the Responses API that uses the OpenAI CUA wire shape and can be driven with the stock `openai` SDK. SAM 3.1 is hosted as `sam-3.1` on the same endpoint and costs $2.50 per 1,000 images, but it returns special-token text with base85 masks, not JSON. On prior art, nobody was found doing the full pipeline: a fixed protective intent, a baseline-vs-candidate agent run, deterministic deltas, visual evidence and a PR gate. AgentA/B, the dark-pattern susceptibility benchmarks and DarkLens each cover part of it, so the novelty claim has to be the combination and not any single piece. Prior art also shows that agents fall for the very patterns AgencyDiff measures. The design therefore needs a final-state oracle and deltas computed deterministically, not raw agent step counts.

## Muse Spark computer use is OpenAI-CUA-shaped and bring-your-own-browser

The Meta Model API lives at **`https://api.meta.ai/v1`** with `Authorization: Bearer $MODEL_API_KEY` ([Authentication](https://dev.meta.ai/docs/authentication.md)). There is no Meta SDK: use the `openai` package with `base_url` set and `api_key` passed explicitly, because the SDK will not read `MODEL_API_KEY` on its own ([SDKs](https://dev.meta.ai/docs/sdks.md)). The recommended model is **`muse-spark-1.3`**, with a 1,048,576-token context and text, image, video, audio and PDF input. **`muse-wonder-1.0`** is the stronger and pricier preview model, and Meta's computer-use guide uses it by default ([Models](https://dev.meta.ai/docs/models.md)). Spark Standard costs **$1.25 in / $4.25 out per 1M tokens**. The `-contributor` variant costs $0.10/$0.20 but allows Meta to train on your data and is capped at **150 RPM**. Wonder costs $4/$20. Standard models get 3,000 RPM and 4M TPM per team ([Pricing and rate limits](https://dev.meta.ai/docs/pricing-rate-limits.md)). A ~1280px screenshot costs about 1,300–1,500 input tokens ([Image understanding](https://dev.meta.ai/docs/image-understanding.md)), or roughly $0.002 per turn on Spark Standard before history replay. The $150 credit is enough for a demo-scale probe suite if history is pruned.

The native tool is **`{"type":"computer"}` and works on the Responses API only**. It has no display or environment fields. The model returns `computer_call` items with a batched `actions` array (click, double_click, drag, keypress, move, scroll, type, screenshot, wait) in **pixel coordinates of the last screenshot sent**. You answer with `computer_call_output` carrying a PNG/JPEG `computer_screenshot` data URL of 25 MiB or less. **Meta runs no VM**: you supply Playwright or a similar driver ([Computer use guide](https://dev.meta.ai/docs/computer-use.md)). State chains via `previous_response_id`. Stateless replay needs `meta_safety_replay_receipt` echoed back and holds at most 29 call/output pairs. `truncation:"auto"` works only "where it's enabled for your account" and otherwise returns HTTP 400. `pending_safety_checks` must be acknowledged explicitly (same source). A request carries **at most 50 images**, and Meta's own Linux recipe hit that cap ([CU cookbook](https://dev.meta.ai/docs/cookbook/computer-use.md)). For function tools, **`tool_choice` must be `"auto"`**, and structured output on Responses uses `text.format`, not `response_format` ([Tool calling](https://dev.meta.ai/docs/tool-calling.md); [Structured output](https://dev.meta.ai/docs/structured-output.md)).

There are three conventions to keep apart. The native tool uses screenshot pixels. VLM grounding and the `metacua` macOS reference agent use a **normalized 0–1000 grid**, and `metacua` defines a function tool that mirrors Anthropic's `computer_20251124` rather than using the native tool ([macOS recipe](https://dev.meta.ai/docs/cookbook/computer-use-macos.md)). Reliability is thin. Meta reports Spark 1.3 benchmark scores only as images. Aggregators cite a **66.9% OSWorld 2.0 partial score** with a binary completion rate of about 32 ([docsbot.ai](https://docsbot.ai/models/compare/muse-spark-1-3/muse-spark); [BenchLM](https://benchlm.ai/models/muse-spark-1-3)), and Spark 1.1 figures conflict (80.8 vs 53.3%). **Unverified items:** latency, whether `truncation:"auto"` is enabled on hackathon accounts, and whether the native `computer` tool can share a request with function tools. Geographic availability may also vary; the July launch was US-only ([Models](https://dev.meta.ai/docs/models.md)).

## SAM 3.1 is cheap per screenshot but speaks a token grammar

SAM 3.1 runs as model **`sam-3.1` via `POST /v1/responses`**. One user message carries one `input_text` prompt and one `input_image` or `input_video` ([Segmenting](https://dev.meta.ai/docs/sam/segmenting.md)). Prompts take one of two forms that cannot be mixed. The first is a **single noun phrase** ("button"), which returns every instance. Lists such as "bus, bicycle" return zero matches, and zero matches come back as empty `output_text`, not an error. The second is a **box/point token grammar**, for example `<0f>1<|point;x=..;y=..;w=W;h=H|>`, where `w`/`h` must equal the media's pixel size or the call returns 400 (same source). The output is **special-token text**: per-frame lines with box corners in source pixels and mask `data=H,W,<enc>` where the **payload is base85, not base64** and the raster is smaller than the frame. Optional confidence is enabled with `metadata.include_confidence: "true"` as a string ([Reading segmentation output](https://dev.meta.ai/docs/sam/reading-segmentation.md)). Use the official parsers, **`meta-sam-parser`** (Python ≥3.10: `decode_mask_to_raster`, `decode_mask_to_rle`, `decode_mask_to_svg_path`, `build_object_prompt`) or `@meta-sam/parser` (TS) ([Client libraries](https://dev.meta.ai/docs/sam/client-libraries.md)).

Images cost **$2.50 per 1,000** and video $0.20 per 1,000 frames with a 50-frame minimum per request, at 3,000 RPM and no TPM limit ([Pricing](https://dev.meta.ai/docs/pricing-rate-limits.md)). Limits are 16 objects per frame or request, MP4/MOV H.264/H.265 only, and up to 15,000 frames ([Segmenting](https://dev.meta.ai/docs/sam/segmenting.md)). Results "can vary slightly between runs", so SAM masks belong in the evidence layer and not in the pass/fail computation. Open weights (`facebook/sam3.1`, 848M params, gated, SAM License, needs CUDA 12.6+) exist as a fallback ([facebookresearch/sam3](https://github.com/facebookresearch/sam3)). **Unverified items:** hosted latency, maximum image resolution, and exactly how the smaller mask raster maps onto frame pixels.

## No one runs a matched-intent version diff as a PR gate

The closest neighbor is **AgentA/B**, which already runs LLM agents on two interface variants of live sites. In a 1,000-agent Amazon case study, its directional result matched a human experiment ([arXiv 2504.09723](https://arxiv.org/html/2504.09723v2)). It differs from AgencyDiff in three ways: it optimizes commercial outcomes using persona populations, it reports stochastic rates, and it is not a CI gate. **SusBench** (313 tasks, 123 injected patterns), **TrickyArena** (agents fall for one pattern ~41% of the time) and **DECEPTICON** (>70% for agents vs 31% for humans) toggle dark patterns on and off, but they test agent susceptibility, not product versions ([arXiv 2510.11035](https://arxiv.org/abs/2510.11035v1); [arXiv 2510.18113](https://arxiv.org/abs/2510.18113); [arXiv 2512.22894](https://arxiv.org/abs/2512.22894v1)). On the developer side, **DarkLens** is a GitHub Action that scores a preview URL's live DOM across 26 categories, including GDPR consent and click-to-cancel, and fails builds below 70. Its README shows no baseline-vs-PR diff and no agent execution ([darklens-actions](https://github.com/bhanu403/darklens-actions)). **AutoBot** ships a Lighthouse dark-pattern audit as a per-page classifier ([arXiv 2411.07441](https://arxiv.org/html/2411.07441v4)). Visual-regression tools such as Percy supply the approve-baseline PR workflow but diff pixels, not task cost ([bug0](https://bug0.com/knowledge-base/visual-regression-testing-tools)).

The defensible claim is therefore narrow and systems-level. It has five parts: hold a user-protective intent fixed as the oracle, vary only the product version, reduce the agent traces to deterministic, regulation-aligned deltas (step and depth counts, first-view visibility, default state, accept/reject asymmetry, reversibility cost), attach replayable SAM-grounded evidence, and gate this in the PR. The metrics are already law-shaped rather than novel. The EDPB requires reject on the same layer as accept ([EDPB taskforce report](https://www.edpb.europa.eu/system/files/2023-01/edpb_20230118_report_cookie_banner_taskforce_en.pdf)). Removing a first-layer reject button raised consent by **22–23 pp** in Nouwens et al.'s field experiment ([arXiv 2001.02479](https://arxiv.org/abs/2001.02479v1)). The FTC's click-to-cancel rule was **vacated on July 8, 2025** ([Greenberg Traurig](https://www.gtlaw.com/en/insights/2025/7/eighth-circuit-vacates-ftcs-click-to-cancel-rule)), so the regulatory pitch should lead with GDPR/EU and keep cancellation parity as a ROSCA and state-law argument. Do not claim to be the first to use agents on dark patterns, the first to measure accept/reject asymmetry, the first to compare UI versions with agents, or the first dark-pattern PR check. The search was about 20 queries, not exhaustive, so run one GitHub search for "consent regression" or "dark pattern regression playwright" before using the word "first" at all.

The validity threat comes from the same literature. Agents accepted cookies in 14.4% of trials even when told to deny all ([ACM DL](https://dl.acm.org/doi/10.1145/3772363.3799048)), and agent paths diverge from human paths even when success rates are similar ([arXiv 2604.07929](https://arxiv.org/html/2604.07929)). An agent on the candidate version can "succeed" by taking the manipulated path, which would make the diff understate the harm. Agent step counts are a noisy signal, not ground truth.

## Conclusion

The API risk is low and the rules and validity risks are high. AgencyDiff's credibility depends on the agent serving only as an explorer, with the verdict computed deterministically from final state and the DOM or accessibility tree. That design also answers the obvious judge question, "isn't this just flaky agent output?". The pattern-toggle method from SusBench and TrickyArena turns into a ready-made validation set: inject a known regression into a candidate build and show that AgencyDiff catches it while a DarkLens-style snapshot scorer cannot tell the two builds apart. That is the demo's "it works" moment and its novelty proof in a single shot.
